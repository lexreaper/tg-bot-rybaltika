# Хаб сети Мануфактура и Telegram Mini App

Модуль меню из первого спринта сохранён. По первым четырём задачам документа
«Спринт 2» добавлены **афиша, вакансии, информационная страница лояльности и макеты
новых страниц и административных экранов**. Исполнитель: Кузнецов Семён.

## Быстрый запуск на Windows

Открой PowerShell или CMD в корне проекта — там, где лежит `run_demo.py`.
Если виртуальное окружение уже есть, первую команду повторять не нужно.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_demo.py --editor
```

Сервер напечатает **адрес редактора и случайный ключ для этого запуска**.
Вставь этот ключ в форму редактора. После перезапуска ключ может быть другим,
а сохранённый текст останется в базе. Без `--editor` можно запускать только
публичное приложение; постоянный ключ редактора задаётся через `.env`.

Адреса после запуска:

| Адрес | Что открыть |
|---|---|
| http://127.0.0.1:8000 | Меню и навигация по разделам |
| http://127.0.0.1:8000/#/events | Афиша |
| http://127.0.0.1:8000/#/vacancies | Вакансии |
| http://127.0.0.1:8000/#/loyalty | Информация о программе лояльности |
| http://127.0.0.1:8000/admin | Работающий редактор текста лояльности |
| http://127.0.0.1:8000/design | Макеты новых страниц и административных экранов |
| http://127.0.0.1:8000/docs | Документация REST API |

Остановить: `Ctrl+C`. Повторно запустить: последняя команда из примера.
Node.js нужен только для браузерных автотестов, сборка frontend не требуется.

macOS / Linux: используй `python3 -m venv .venv`, затем
`.venv/bin/python -m pip install -r requirements.txt` и
`.venv/bin/python run_demo.py --editor`.

## Какие задачи выполнены

| № | Требование второго спринта | Реализация |
|---|---|---|
| 1 | Макеты новых страниц и админ-панели | `/design`: афиша, вакансии, лояльность, списки контента, редактирование мероприятия/вакансии/лояльности, подтверждение удаления |
| 2 | Страница «Афиша» | Карточки с фото, названием, полным описанием и датой; GET `/events`; пустое состояние, ошибки и повтор |
| 3 | Страница «Вакансии» | Должность, описание, оплата; GET `/vacancies`; отсутствующая/пустая оплата показана как «Оплата уточняется» |
| 4 | Информационная лояльность | GET `/loyalty`; текст меняется в защищённом `/admin`, сохраняется в базе и появляется у посетителей |

В Mini App есть общая навигация и поддержка мобильной ширины, темы Telegram,
безопасных отступов и системной кнопки назад. Кнопок бронирования, баллов, уровней,
регистрации участников и начислений в новых разделах нет.

**Граница frontend:** рабочие CRUD-экраны афиши и вакансий здесь не реализованы;
подготовлены их макеты. Единственный рабочий административный экран Mini App —
редактор лояльности. Backend CRUD для баров, мероприятий, вакансий и лояльности
доступен через `/api/hub/admin`.

Mini App API и API хаба используют общие таблицы `events`, `vacancies` и
`loyalty_info`; поля адаптируются к прежнему frontend-контракту. Публикация или
редактирование контента через hub API сразу отражается на публичных страницах
Mini App. Меню по-прежнему хранится в `categories` и `dishes`.

## API после объединения веток

Mini App использует:

- `/menu`, `/menu/categories`, `/menu/dishes/{id}` — меню;
- `/events`, `/vacancies`, `/loyalty` — опубликованный контент для страниц;
- `/admin/loyalty` — редактор страницы лояльности с ключом `CONTENT_ADMIN_TOKEN`.

API хаба использует отдельный префикс:

- `GET /api/hub/bars`, `/api/hub/events`, `/api/hub/vacancies`,
  `/api/hub/loyalty` — опубликованные записи;
- `/api/hub/admin/...` — CRUD для баров, мероприятий, вакансий и лояльности,
  доступный с `Authorization: Bearer <ADMIN_API_TOKEN>`.

Это два разных admin-контракта: `CONTENT_ADMIN_TOKEN` нужен только экрану
редактирования лояльности Mini App; `ADMIN_API_TOKEN` защищает CRUD API хаба.
Для локальной демонстрации `run_demo.py --editor` автоматически создаёт
временный ключ редактора.

## Данные и хранение

Демонстрация явно включает `DEMO_MODE=true` и использует SQLite `demo.db`.
В браузере выполняются настоящие REST-запросы к Python-серверу; данных мероприятий,
вакансий и лояльности в публичном JavaScript нет.

При первом запуске добавляются примерные мероприятия, вакансии и информационный
текст. Это учебные данные, фотографии иллюстративные, суммы не являются реальными
условиями ресторана. Также есть неопубликованные записи для проверки фильтрации.
При повторном запуске отредактированный текст не перезаписывается.

Старый `demo.db` можно оставить: недостающие таблицы создаются автоматически,
данные меню сохраняются. Файл базы и установленные зависимости в архив не включены.
Не удаляй рабочую базу ради запуска новых страниц.

## Как показать результат

1. Открой `/design` и покажи макеты первых четырёх задач.
2. В приложении перейди из меню в афишу: название, дата, изображение, описание.
3. Открой вакансии: покажи известную оплату и «Оплата уточняется» у официанта.
4. Открой лояльность: это информационный текст без бонусного счёта.
5. В `/admin` войди ключом из консоли, измени текст, сохрани.
6. Обнови раздел лояльности в приложении: виден сохранённый текст.
7. Сними «Показывать посетителям» и сохрани: посетитель увидит пустое состояние.
   Затем снова опубликуй страницу.

Для Telegram запусти сервер и во втором терминале:

```powershell
ssh -o ServerAliveInterval=60 -R 80:127.0.0.1:8000 nokey@localhost.run
```

Полученную HTTPS-ссылку открой в браузере, затем поставь в
BotFather → `/setmenubutton` → ваш бот. Оба процесса должны оставаться запущенными.
Если адрес туннеля поменяется, обнови его в BotFather. Токен Telegram не нужен для
показа этого Mini App: сервер обрабатывает HTTP-запросы, не сообщения бота.

## Основной PostgreSQL-режим

Скопируй `.env.example` в `.env`, заполни DB-параметры, оставь `DEMO_MODE=false`.
Для постоянного редактора добавь `CONTENT_ADMIN_TOKEN` длиной минимум 24 символа.
Ключ можно сгенерировать локально:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
```

Затем запусти `docker compose up --build` с доступной PostgreSQL. Приложение
применит миграции Alembic. Они сохраняют `categories` и `dishes`, переносят
содержимое старых `site_events`, `site_vacancies` и `loyalty_page` в общие таблицы,
после чего удаляют исходные таблицы Mini App. Также удаляются неиспользуемые
таблицы старой схемы бронирований (`users`, `bookings`, `reviews`); эти данные
будут потеряны. Перед миграцией рабочей базы сделай резервную копию.

Рабочая база автоматически не заполняется учебным содержимым. Контент добавляется
через `/api/hub/admin/...` либо страницу `/admin` для лояльности.

### Заполнение тестовыми данными

После запуска Docker-сервисов и успешного применения миграций открой PowerShell
в корне проекта и выполни:

```powershell
docker compose exec web python -m scripts.seed_test_data
```

Скрипт добавляет примерное меню, мероприятия, вакансии, лояльность и тестовые бары
только в пустые разделы. Повторный запуск безопасен: уже существующие записи не
перезаписываются и не удаляются. Запускать скрипт нужно внутри контейнера `web`,
чтобы он подключился к базе по Docker-адресу `db`. Для этого не нужно открывать
shell контейнера или запускать скрипт внутри контейнера PostgreSQL. Чтобы проверить
результат, открой `/docs` или страницы Mini App.

Редактор использует простой общий ключ в `X-Admin-Token`, хранит его в памяти
страницы и не кладёт в frontend-конфиг или URL. Это минимальная проверка прав для
этого модуля; общая админ-панель с учётными записями остаётся задачей команды.
Исходные POST `/menu/dishes` и `/images/upload` не менялись: в текущем коде у них
нет авторизации. Не считай их закрытыми новым ключом редактора.

## Где что находится

- `frontend/assets/app.js` — маршруты и меню первого спринта.
- `frontend/assets/api.js` — общий REST-клиент с таймаутом и обработкой ошибок.
- `frontend/assets/content.js`, `content.css` — три новые публичные страницы.
- `frontend/admin.html`, `assets/admin.js`, `assets/admin.css` — редактор лояльности.
- `frontend/design.html` — HTML-макеты, можно открыть как файл или через `/design`.
- `frontend/assets/config.js` — адрес сервера и пути новых API.
- `app/api/routers/content.py`, `schemas/content.py` — новый REST-контракт.
- `app/db/model.py` — общие SQLAlchemy-модели контента и меню.
- `migrations/versions/20261030_0003_merge_frontend_and_hub.py` — перенос прежних
  записей Mini App в общую схему.
- `app/demo_content.py` — демонстрационное наполнение.
- `docs/SPRINT2.md` — критерии приёмки и передача задач команде.
- `docs/API.md`, `docs/UI-UX.md`, `docs/TESTING.md` — контракт, макеты и проверки.
- `docs/MENU-SPRINT1.md` — сохранённая инструкция предыдущего спринта.

После переноса в свой репозиторий не заменяй `.git` и `.env`. Сначала запусти и
проверь, затем коммить изменения в `front`. Файл `.env`, базы, ключи, `.exe` и
установленные зависимости не должны попадать в коммит.
