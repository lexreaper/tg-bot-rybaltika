# Проверки

## Выполнено в среде разработки

- **26 тестов pytest пройдено.** Настоящие FastAPI-запросы через TestClient,
  SQLAlchemy и временная SQLite: полный путь категории → блюда → карточка,
  неизвестные и неправильные id, скрытые блюда, пустая категория, nullable фото,
  отказ базы с безопасной ошибкой 503, повторное заполнение демобазы, раздача UI.
- **19 проверок меню и 21 проверка второго спринта Playwright пройдены.** Настоящий Chromium и локальный
  FastAPI: навигация, поиск, состав, цены, загрузка фото, возврат с сохранением
  поиска, отсутствие фото, 404, 503 и повтор, пустое меню/категория, неверный JSON,
  битая картинка, экранирование HTML из API, таймаут, быстрые переходы, отсутствие
  горизонтальной прокрутки на 320/390/1280 px, отсутствие необработанных JS-ошибок.
- Telegram ready/expand, тёмная тема и BackButton проверены **с имитацией SDK**.
- Экраны меню и новые страницы визуально просмотрены в Chromium.

Новые серверные тесты проверяют публикацию/скрытие событий и вакансий, пустые
ответы, чтение лояльности, отключённый редактор, отказ без ключа, сохранение,
скрытие и повторную публикацию, конфликт версий, ограничения полей и ошибку базы.
Миграция старой схемы в новую выполнена на SQLite с сохранением существующего меню.
SQL миграций также успешно сгенерирован для PostgreSQL без подключения к базе.

Новые браузерные проверки включают реальные GET новых разделов, дату и фото афиши,
неизвестную оплату, пустые страницы, ошибки с повтором для каждого раздела, битое
фото, неверную дату, экранирование текста из API, независимость от меню,
конфигурируемые пути API, вход в редактор, сохранение и отображение текста,
ошибку сохранения без потери ввода, скрытие публикации и адаптивность 320/390/1280 px.
Публичные страницы, рабочий редактор и восемь макетов визуально просмотрены.

Тесты не заменяют проверку на реальных клиентах Telegram.
В этой среде не запускались PostgreSQL, Docker Compose, S3 и реальный Telegram-бот.
Рабочий домен, токен и реальные данные ресторана не предоставлены.

## Повторить серверные тесты

В активированном Python-окружении:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

На Windows вместо `python` можно использовать `.\.venv\Scripts\python.exe`.
Тесты создают отдельную временную SQLite, рабочую базу не меняют.

## Повторить браузерные тесты

В первом терминале: `python run_demo.py`.
В другом терминале в той же папке (нужен Node.js 20+):

```bash
npm install
npx playwright install chromium
npm run test:browser
```

Node.js нужен только для автотестов, не для приложения.
Проверки рассчитаны на исходные демоданные. Если менял demo.db, сначала останови
демосервер и сбрось только этот демонстрационный файл, затем запусти снова.
`TEST_BASE_URL` позволяет указать другой адрес сервера.

## Совместная приёмка команды

| Действие | Ожидаемый результат |
|---|---|
| Открыть меню в Telegram iOS и Android | Интерфейс внутри Mini App, нет наложения на системные элементы |
| Выбрать категорию | GET /menu?category_id=…; только её доступные блюда |

## Как показать ошибку вручную

В браузере открой DevTools → Network → Offline, затем выбери другую категорию.
Дождись ошибки, верни Online и нажми «Попробовать снова».
Для проверки 404 открой `http://127.0.0.1:8000/#/dish/99999`.


## Проверить второй спринт в браузере

В отдельной локальной тестовой папке используй демонстрационную базу, а не рабочую.
В Windows PowerShell в первом терминале:

```powershell
$env:CONTENT_ADMIN_TOKEN = "test-only-content-key-0123456789012345"
.\.venv\Scripts\python.exe run_demo.py
```

Во втором терминале после установки Playwright по инструкции выше:

```powershell
$env:TEST_ADMIN_TOKEN = "test-only-content-key-0123456789012345"
npm run test:browser:sprint2
```

Это публичное тестовое значение, не используй его как рабочий ключ.
Тест изменяет только текст демонстрационной лояльности и восстанавливает исходный
текст в finally. Исходные тесты меню запускаются через `npm run test:browser`.

Настоящий ключ редактора для демонстрации генерируй через `run_demo.py --editor`.
