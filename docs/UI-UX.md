# UI/UX — Кузнецов Семён

## Концепция

Светлый ресторанный интерфейс: тёплый фон #F5F2EB, тёмный текст #292D25,
терракотовый акцент #773C32. Заголовки Georgia, основной текст Arial: системные
шрифты не требуют внешней загрузки. В Telegram доступна тёмная тема.
Основной макет — телефон шириной 390 px, поддерживаются 320 px и desktop.

## Три экрана

1. **Категории.** Логотип и название сверху; короткое вступление; далее плитки
   категорий с названием, количеством доступных блюд и фотографией. Вся плитка
   кликабельна. Первая категория выделена шириной. Категории приходят от API.
2. **Блюда категории.** «Все категории» сверху, заголовок, горизонтальное
   переключение категорий, поиск по названию и составу внутри выбранной категории.
   У блюда слева фото, справа название, короткий состав, цена и стрелка перехода.
   Пустой результат поиска объясняется текстом. Поиск работает локально по
   загруженному списку; новый API-запрос при вводе не требуется.
3. **Карточка.** Кнопка назад, крупная фотография, название, цена, полный состав,
   примечание об аллергии и явный возврат к блюдам. Это модуль просмотра меню:
   кнопок оформления заказа в нём нет.

Статические макеты всех трёх экранов: `/design` или `frontend/design.html`.
Они показывают демонстрационный контент и не зависят от текущего меню в базе.

## Сценарий

Открыть меню → выбрать категорию → просмотреть/найти блюдо → открыть карточку →
прочитать состав и цену → вернуться к списку → выбрать другую категорию.
При возврате восстанавливаются поисковая строка и позиция прокрутки списка.
Прямые ссылки: `/#/`, `/#/category/1`, `/#/dish/1`.
Системная BackButton Telegram возвращает с карточки в её категорию, со списка —
к категориям; на главной скрыта. Браузерная история тоже работает.

## Состояния и доступность

- Загрузка: skeleton и текст для screen reader, `aria-busy`.
- Ошибка сети/сервера/таймаут: понятное сообщение и повтор того же запроса.
- 404: объяснение и переход к категориям.
- Пустое меню/категория/поиск: отдельные объяснения, без ложных блюд.
- Нет/не загрузилось фото: заглушка «Фото скоро появится».
- Нет состава: предложение уточнить у официанта.
- Длинные названия: переносятся; краткий состав в списке ограничен двумя строками.
- Клавиатура: ссылки и поля доступны по Tab, видимый focus, alt у фотографий.
- Новая навигация отменяет предыдущие запросы: медленный ответ не заменит новый экран.
- Поддерживаются уменьшение анимации, тема Telegram и safe area телефона.

Макеты — HTML, а не файл Figma. Для сдачи открывай страницу `/design`.

# Макеты и страницы второго спринта

Текущий `/design` посвящён четырём задачам спринта 2, предыдущий просмотр меню
сохранён в приложении. Общая визуальная система остаётся прежней.

## Публичные экраны

- Афиша: заголовок раздела, пояснение, карточки событий. Сверху фотография и дата
  в плашке, ниже полная дата с годом, название и описание. На телефоне одна колонка,
  на большом экране — две. Бронирование не показано.
- Вакансии: заголовок, вводный текст, карточки с должностью и полным описанием.
  Оплата выделена в нижней части карточки и подписана как ориентировочная.
  Неизвестная оплата не превращается в 0 рублей.
- Лояльность: заголовок и краткое описание, спокойная фирменная иллюстрация,
  основной текст абзацами. Действие «К нашему меню» возвращает к категориям.
  Все сведения страницы приходят из API, утверждённых правил бонусов не выдумываем.

На телефоне постоянная нижняя навигация: Меню / Афиша / Вакансии / Лояльность.
Под неё оставлен отступ, включая safe area. На desktop навигация находится сверху.
Активный пункт различается по фону, цвету и aria-current. Telegram BackButton из
нового раздела ведёт к меню, из карточки блюда — к её категории.

## Административные макеты

В `/design` показаны список контента, формы мероприятия, вакансии и лояльности,
а также подтверждение удаления. Поля и порядок действий соответствуют плану:
из списка открыть запись → изменить поля → выбрать публикацию → сохранить;
для удаления — отдельное подтверждение.
У события: фото, название, описание, дата и публикация. У вакансии: должность,
описание, необязательная оплата и публикация. Лояльность редактируется как одна
информационная страница с предпросмотром.

## Рабочий редактор лояльности

Отдельный `/admin` предназначен сотруднику. Сначала ключ доступа, затем форма:
заголовок, короткое описание, основной текст и «Показывать посетителям».
Предпросмотр отражает ввод, но публичная страница меняется только после сохранения.
Показаны статусы сохранения и ошибки; при неуспешном сохранении текст не теряется.
При конфликте версии предлагается загрузить актуальную версию с подтверждением
замены несохранённых полей. Ключ не сохраняется между перезагрузками страницы.
