# Контракт REST API

Базовый адрес — тот же, что у Mini App. Все GET доступны без авторизации:
меню публичное. Формат — JSON, цены в рублях. Существующие пути не переименованы.

| Метод и путь | Ответ | Ошибки |
|---|---|---|
| GET `/menu/categories` | Массив категорий, включая пустые | 503 — ошибка базы |
| GET `/menu?category_id=1` | Только доступные блюда категории | 404 — нет категории; 422 — неверный id; 503 — база |
| GET `/menu` | Все доступные блюда | 503 — база |
| GET `/menu/dishes/1` | Одно доступное блюдо | 404 — нет/недоступно; 422 — id не число; 503 — база |

Категории сортируются по `sort_order`, затем `id`. Блюда — по порядку категории,
затем id. `dish_count` учитывает только доступные блюда. Обложка категории — первое
доступное блюдо с непустым `image_url`. Пустая категория имеет `dish_count: 0`,
`image_url: null` и возвращает пустой массив блюд, а не 404.

```json
[{"id":1,"name":"Рыба и морепродукты","sort_order":1,"dish_count":3,"image_url":"/assets/salmon.jpg"}]
```

```json
{"id":1,"category_id":1,"name":"Лосось на гриле","description":"Филе лосося, овощи, лимон.","price":"890.00","image_url":"/assets/salmon.jpg","is_available":true}
```

В исходной модели нет отдельного поля состава: **`description` используется как
состав блюда**. Это сохраняет совместимость без изменения таблиц. Если Backend
позже добавит `ingredients`, нужно согласованно обновить схему ответа и UI.
`price` сериализуется из Decimal как строка, frontend форматирует её как рубли.
`image_url` и `description` могут быть null. Изображения допускаются по HTTP/HTTPS
(для Telegram используй HTTPS или относительные пути). При битой ссылке — заглушка.

Ошибки FastAPI возвращаются как `{"detail":"..."}`. В UI используются безопасные
понятные сообщения для 404, сети, таймаута (10 секунд), некорректного JSON и 5xx.
Технические детали SQL записываются на сервере и не передаются клиенту.

## Пример заполнения пустой учебной PostgreSQL

После запуска миграций, только в отдельной учебной базе:

```sql
INSERT INTO categories (name, sort_order) VALUES ('Рыба и морепродукты', 1);
INSERT INTO dishes (category_id, name, description, price, image_url, is_available)
SELECT id, 'Лосось на гриле', 'Филе лосося, овощи, лимон.', 890.00,
       '/assets/salmon.jpg', true
FROM categories WHERE name = 'Рыба и морепродукты';
```

Это не идемпотентный импорт: не запускай повторно в заполненной базе.
Для реального меню внесите реальные категории, цены, составы и фотографии.

## Разные адреса клиента и сервера

В `frontend/assets/config.js`: `apiBaseUrl: 'https://api.example.com'`.
На backend: `CORS_ORIGINS=["https://miniapp.example.com"]` в `.env`.
Относительные пути фото разрешаются от адреса API. Секреты не нужны frontend.
Рекомендуемый вариант — одна точка входа через reverse proxy, без CORS.

# API новых разделов второго спринта

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/events` | Опубликованные мероприятия, по дате и id |
| GET | `/vacancies` | Опубликованные вакансии, по id |
| GET | `/loyalty` | Опубликованная страница или `null` |
| GET | `/admin/loyalty` | Полный текст, статус и версия; нужен X-Admin-Token |
| PUT | `/admin/loyalty` | Сохранённая страница; нужен X-Admin-Token |

Пример мероприятия:

```json
{"id":1,"title":"Вечер сезонной кухни","description":"Описание вечера.","date":"2026-11-05","image_url":"/assets/salmon.jpg"}
```

`date` — календарная дата YYYY-MM-DD, не timestamp. Изображение может быть null.
Пустой список — `[]`. В публичный ответ не попадают черновики.

Пример вакансии:

```json
{"id":1,"position":"Официант","description":"Обязанности и требования.","salary":null}
```

`salary` — необязательный текст: `от 65 000 ₽ в месяц`, `По договорённости` или
null. Клиент не преобразует это поле в число. Пустое значение — «Оплата уточняется».

Публичная лояльность:

```json
{"title":"Программа лояльности","summary":"Краткое описание","body":"Первый абзац.\n\nВторой абзац.","updated_at":"2026-10-27T12:00:00Z"}
```

Если страница не создана или скрыта, GET `/loyalty` возвращает `null` с кодом 200.
Во всех разделах отказ базы — 503 с безопасным сообщением без SQL/секретов.
Клиент использует `cache: no-store`, поэтому после сохранения и перехода/обновления
отображается актуальный текст. Обновления по WebSocket не предусмотрены.

## Редактирование лояльности

На сервере задаётся `CONTENT_ADMIN_TOKEN` длиной не менее 24 символов.
Если он не настроен, административные методы возвращают 503. Если ключ отсутствует
или неверен, возвращается 401. Токен передаётся только в заголовке `X-Admin-Token`.
Он не входит в JSON приложения, конфиг frontend, URL или браузерное хранилище.

GET `/admin/loyalty` возвращает публичные поля плюс `is_published` и `version`.
У ещё не созданной страницы `version=0`, строки пустые, публикация выключена.
PUT принимает:

```json
{"title":"Программа лояльности","summary":"Краткое описание","body":"Новый текст","is_published":true,"expected_version":1}
```

- `title`: от 1 до 120 символов после обрезки пробелов.
- `summary`: до 300 символов, может быть пустой строкой.
- `body`: от 1 до 10 000 символов, обычный текст с абзацами.
- `is_published`: boolean.
- `expected_version`: версия последнего GET, 0 для новой страницы.

При успехе возвращается страница с увеличенной версией. При несовпадении версии —
409, при неверных полях — 422. Перед повтором после 409 нужно перечитать страницу
и согласовать изменения, а не просто увеличить expected_version вручную.

Это минимальный редактор пункта 4. Общий CRUD API хаба подключён отдельно под
`/api/hub/admin`, чтобы сохранить контракт редактора и публичных страниц Mini App.

## API хаба

Публичные GET-маршруты:

| Метод и путь | Назначение |
|---|---|
| GET `/api/hub/bars` | Опубликованные бары |
| GET `/api/hub/events` | Опубликованные мероприятия |
| GET `/api/hub/events/{event_id}` | Опубликованное мероприятие |
| GET `/api/hub/vacancies` | Опубликованные вакансии |
| GET `/api/hub/loyalty` | Опубликованная информация о лояльности |

Административный CRUD доступен под `/api/hub/admin` и требует
`Authorization: Bearer <ADMIN_API_TOKEN>`. Он предоставляет GET/POST/PATCH/DELETE
для bars, events, vacancies и loyalty. Этот токен не является Telegram-
аутентификацией: это отдельный серверный ключ для API хаба. Редактор Mini App
остаётся отдельным: `/admin/loyalty` использует `CONTENT_ADMIN_TOKEN`.

Оба API читают и изменяют одни и те же записи в `events`, `vacancies` и
`loyalty_info`; Mini App адаптирует поля общего контракта (`starts_at` → `date`,
`title` → `position` или `body` → `content`). Изменения через hub API отражаются
на страницах Mini App. Публичные методы обоих API показывают только записи с
`is_published=true`.

Миграция `20261030_0003` переносит существующие данные из прежних таблиц
`site_events`, `site_vacancies` и `loyalty_page`, затем удаляет эти дубликаты.
Перед применением миграций к существующей рабочей базе сделайте резервную копию.

Для другого origin добавь его в `CORS_ORIGINS`. Разрешены методы GET, POST, PATCH,
PUT и DELETE, а также заголовки `Authorization`, `Content-Type` и
`X-Admin-Token`.
